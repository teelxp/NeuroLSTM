# NeuroLSTM 2.0 — физически-информированная рекуррентная модель

Программная реализация выбранных методов докторской диссертации Е. В. Пальчевского «Методологические основы обработки информации 5V на основе интеграции физических и нейросетевых моделей и методов в гибридных интеллектуальных системах для поддержки принятия решений».

Основание этой редакции: PDF `Пальчевский_диссертация_исправленная_нумерация.pdf`, 323 страницы. Идентификатор исходного документа и SHA-256 приведены в `docs/SOURCE_IDENTITY.json`. Сам документ, реальные измерения и прежние обученные веса в поставку не включены.

**Это новая исполняемая реализация, а не восстановленная версия кода исторического эксперимента.** Статистические показатели и время обучения рассчитываются при запуске, а не копируются из таблиц диссертации. Проверка исходного кода и синтетический запуск не подтверждают численные результаты работы.

## Что реализовано

Газовый нейросетевой модуль содержит адаптивную ячейку по (4.20), сгруппированные окна `(B,T,G,F)`, прогнозирование давления и опционально расхода и аварийного состояния. Физический функционал (4.8)–(4.11) использует изменение запаса сжимаемого газа, вычисляемого через прогнозируемое давление, температуру и коэффициент сжимаемости. Измеренный входной расход не объявляется целевым выходным расходом. Дублирования одного физического штрафа под двумя названиями нет.

Обучение выполняется с раздельными градиентами данных, физики и, при наличии размеченных семантических данных, семантики. Регуляризованные проекции (3.98)–(3.100) реализованы буквально, включая `epsilon` и приоритет направления данных. Это не PCGrad и не утверждение о точной ортогональности при ненулевом `epsilon`. Веса ограничений увеличиваются по (3.101)–(3.102).

Дополнительно реализованы EV-k-Means по (2.25)–(2.30), семантические операторы причинной, фазовой, сетевой, волновой и энтропийной согласованности, отдельная газовая PINN по (6.4)–(6.7), критерий архитектуры по всем пяти компонентам 5V, ядро оценки согласованности и ранжирования альтернатив. Для межотраслевого применения предоставлены базовые гидрологические и электроэнергетические операторы невязок.

**Границы поставки:** это нейросетевое и расчетное ядро для репозитория NeuroLSTM, не полный Django-проект СППР. Здесь нет готового веб-интерфейса, диспетчерских команд оборудованию, расчетов безопасных расстояний при взрыве, внешней LLM и восстановленных Java-реализаций «Паводок 2.0». Набор поддерживаемых формул и инженерных конкретизаций подробно указан в `docs/IMPLEMENTATION_MAP.md`.

## Установка

Локальные проверки этой поставки выполнены с Python 3.13.5 и CPU-сборкой PyTorch 2.10.0. Зафиксированные версии зависимостей находятся в `requirements.txt`. Отдельная проверка на CUDA и живой PostgreSQL в эту поставку не входит.

В Windows:

```powershell
py -3.13 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
```

В Linux/macOS:

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Далее команды предполагают активированное виртуальное окружение. Вместо `python` можно всегда указывать полный путь к его интерпретатору. Для GPU необходимо установить совместимую с конкретным оборудованием CUDA-сборку PyTorch. Код не меняет драйверы и не устанавливает пакеты самостоятельно.

## Быстрый функциональный запуск

```bash
python Neuro.py demo --output artifacts/demo --with-semantics
python Neuro.py validate-data --config artifacts/demo/demo_config.json
python Neuro.py train --config artifacts/demo/demo_config.json --output artifacts/run_demo
python Neuro.py evaluate --checkpoint artifacts/run_demo/best.pt --output artifacts/eval_demo
python Neuro.py predict --checkpoint artifacts/run_demo/best.pt --csv artifacts/demo/synthetic_telemetry.csv --output artifacts/forecast_demo.json
```

Генератор создает **явно синтетические данные** и файл `PROVENANCE.json`. В этом примере используются уменьшенная сеть `16 × 2`, три эпохи и синтетические семантические признаки. Это проверка исполнения, а не эксперимент главы 6 и не измерение качества понимания реального текста.

Повторный запуск в непустую папку не перезаписывает результаты. Для нового эксперимента следует выбрать другую папку. Пример конфигурации со всеми семантическими компонентами создается флагом `--with-semantics`; он не обращается к внешним языковым сервисам.

## Выбор конфигурации по диссертации

Исходный текст содержит несовпадающие постановки. Поэтому они не объединены в якобы единственную подтвержденную экспериментальную конфигурацию.

| Файл | Постановка | Разбиение | Минимальный шаг |
|---|---|---|---|
| `configs/gas_ch6_table.json` | Трехвыходная модель: давление, расход, аварийный логит; 100 нейронов, 3 слоя, 25 000 эпох; параметры таблицы 6.1 | train 80 %, validation 0 %, test 20 % | `1e-4`, как в таблице |
| `configs/gas_ch6_validation.json` | Та же архитектура с независимым выбором лучшей модели | 70/10/20; это явная инженерная конкретизация, а не восстановленное разбиение эксперимента | `1e-6`, как в тексте страницы 256 |
| `configs/gas_ch4_pressure_only.json` | Прогноз только давления; измеренные расходы участвуют в признаках и физическом функционале; аварийный флаг может выводиться из заданных физических порогов | 70/10/20 | `1e-6` |
| `configs/gas_clustered.json` | Мини-батчи после EV-k-Means; единая нейросеть | 70/10/20 | `1e-6` |
| `configs/gas_semantics_template.json` | Шаблон подключения реальных семантических входов; семантика выключена до заполнения `path` и размерностей | 70/10/20 | `1e-6` |
| `configs/pinn_gas.json` | Отдельная пространственно-временная PINN: 6 слоев по 64 нейрона, 20 000 коллокационных точек | Задается масками независимых временных интервалов в NPZ | Отдельные настройки Adam/L-BFGS |

В профиле без validation сохраняется последняя модель после заранее заданного числа эпох; файл `best.pt` помечен `last_epoch_without_validation`, и тест не используется для выбора эпохи. В профиле с validation лучшая модель выбирается только по validation. Классификационный выход хранит логит для устойчивой BCE; вероятность вычисляется сигмоидой.

При одном горизонте трехвыходная сеть `100 × 3` с пятью базовыми входами и физическим каналом содержит **206 303** обучаемых параметра. Базовая PINN `64 × 6` с входами только `x,t` содержит **21 187**. Семантическая голова, дополнительные входы и число горизонтов меняют эти количества; фактическое число сохраняется в паспорте запуска.

## Обучение на своих измерениях

Скопируйте выбранный JSON в новый файл, например `configs/gas_local.json`. Укажите `data.path`, `data.sample_period_seconds`, единицы измерений, смысл влажности и происхождение данных. Предоставьте объем участка, молярную массу и коэффициент сжимаемости: в отдельных колонках либо как обоснованные константы раздела `physics`. Для расчета процента физически согласованных результатов задайте допуск `physics.consistency_tolerance_kg_s`.

Все значения `null` в шаблонах имеют определенный смысл: путь/период требуют заполнения; отсутствующие физические константы требуют соответствующих колонок; `semantics.path=null` выключает семантику; неопределенный допуск оставляет процент физической согласованности неопределенным. Произвольные объемы, температуры будущего интервала и отсутствующий `mass_out` автоматически не придумываются.

```bash
python Neuro.py validate-data --config configs/gas_local.json --output artifacts/data_audit.json
python Neuro.py train --config configs/gas_local.json --output artifacts/gas_run_01
python Neuro.py evaluate --checkpoint artifacts/gas_run_01/best.pt --output artifacts/gas_test_01
```

Перед записью `artifacts/data_audit.json` создайте родительскую папку `artifacts`, если она еще отсутствует. Для `train` и `evaluate` папки создаются автоматически. Полная схема CSV и семантического NPZ находится в `docs/DATA_FORMAT.md`.

Раздел `column_map` переименовывает существующие столбцы. Например, `{"Date and time": "timestamp"}`. Метки аварий берутся из колонки `accident`; альтернативный режим `pressure_thresholds` требует явно заданных физических порогов и помечает, что классифицируется пороговое событие. Старый `target_pressure` не подхватывается автоматически: цели формируются из будущих значений исходной колонки давления. Это исключает скрытое использование заранее смещенной цели с неизвестным горизонтом.

### Полный батч и память

`training.batch_mode="full"` означает **один шаг оптимизатора на всем обучающем наборе за эпоху**. Массив окон не размещается целиком на GPU. По микробатчам накапливаются отдельные исходные градиенты, затем один раз выполняются проекции и один раз — шаг AdamW. Размер микробатча задается `micro_batch_size`; его изменение при отключенных стохастических слоях меняет порядок округления, но не целевую полнобатчевую схему.

Профиль `mini` выполняет отдельный шаг на каждом пакете. Кластеризация применяется именно к этому профилю: перестановка всех примеров при полном градиенте сама по себе не доказывает эффект кластерных мини-батчей.

25 000 эпох на большом наборе могут быть существенно более длительными, чем проверочный запуск. В код не встроено обещание воспроизвести указанное в диссертации время обучения.

### Возобновление

```bash
python Neuro.py train --config configs/gas_local.json --output artifacts/gas_run_01 --resume artifacts/gas_run_01/last.pt
```

Используется исходная папка со всей историей и `best.pt`. Разрешено увеличить `training.epochs`, изменить устройство и частоту контрольных точек; исходные данные, семантический файл, алгоритм и остальные параметры должны сохраняться. Измененная постановка требует новой папки запуска. Сохраняются состояния оптимизатора и генераторов случайных чисел.

### PostgreSQL

```bash
python -m pip install -r requirements-postgres.txt
```

Параметры: `data.source="postgres"`, `data.query_file="scripts/postgres_query.sql"`; DSN передается через переменную `NEUROLSTM_DSN`. Файл `.env.example` — только памятка, он не загружается автоматически. Запрос выполняется в транзакции READ ONLY. Пример SQL необходимо согласовать с реальной схемой: добавлять фиктивные измерения ради прохождения проверки нельзя. Для воспроизведения эксперимента предпочтительна неизменяемая выгрузка CSV с зафиксированным хэшем.

## Результаты запуска

В папке обучения появляются `config.resolved.json`, `scaling.json`, `run_manifest.json`, `history.jsonl`, `best.pt` и `last.pt`. Паспорт содержит версии среды, параметры, границы разбиения, число пригодных окон, хэши данных и исходников, выбранную эпоху и фактическое время обучения.

Команда `evaluate` отдельно записывает `metrics.json` и `predictions.csv`. Доступны MAE/RMSE в физических единицах, доля прогнозов внутри явного допуска, матрица ошибок и F1, MAE/RMS балансовой невязки. Процент прошедших массовый баланс результатов рассчитывается только при заданном допуске. Это не универсальная оценка всех физических законов. Нулевая знаменательная величина в неопределенной классификационной метрике дает `null`, а не произвольные 0 или 100 %.

`predict` использует только прошлые измерения и выдает прогноз. Будущие измеренные расходы, температура и Z не попадают в входной вектор. Физический баланс будущего интервала при этом помечается как **не проверенный**: для его оперативной проверки нужны независимые сценарии будущих воздействий. Расчет доверия и ранжирование не означают выдачу команды на исполнительное оборудование.

## Обновление существующего GitHub-репозитория

Копируется **весь пакет**, включая `neurolstm/`, а не один маленький `Neuro.py`. Прежние веса `best_adaptive_lstm.pth` не подходят новой архитектуре. Их следует сохранить как артефакт прежней версии, не переименовывая в новый `best.pt`.

Безопасный порядок: создать новую ветку, скопировать исходники, выполнить тесты, зафиксировать изменения. Например:

```bash
git switch -c dissertation-implementation
# Скопировать содержимое поставки в рабочую копию репозитория.
python -m pytest -q
git add Neuro.py TrainPINN.py neurolstm configs tests docs scripts examples README.md
git add requirements.txt requirements-dev.txt requirements-postgres.txt pyproject.toml .gitignore .env.example .github/workflows/tests.yml
git commit -m "Implement dissertation-based physical and semantic training"
git push -u origin dissertation-implementation
```

Не публикуйте пароли, реальные данные, `.env` и контрольные точки без проверки состава. `.gitignore` не исключает автоматически файлы, которые были добавлены в Git ранее. Workflow проверки подготовлен, но его выполнение на GitHub подтверждается только реальным запуском Actions после публикации.
